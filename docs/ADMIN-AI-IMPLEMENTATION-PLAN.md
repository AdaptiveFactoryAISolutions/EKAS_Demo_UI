# Proposed V107: Admin → AI configuration

Begin after V106 completes validation and is frozen. This direct user request takes priority over the prepared GAP043 localization package. Preserve all frozen candidates and terminal fallback. Implement/test only fake credentials and mock transport; actual user credential submission, trust provisioning and paid calls remain separate, held actions.

1. Add Admin → AI configuration to existing navigation/visuals, retaining Brief/Explore/Improvements/Knowledge/Metrics. Separate operational configuration from an explicitly labeled mock rehearsal. Show disabled/mock/OpenAI/future-backend modes, configured status, configuration revision, safe model/token/request bounds, activation blockers and truthful budget categories. Advanced settings collapsed; accessible labels, helper text, field errors, keyboard focus and status announcements remain visible.
2. Add server-admin authorization and protected same-origin API contracts. Genuine existing identity or an explicitly documented trustworthy local administrator bootstrap can supply authority; the fictional role selector cannot. Default deny if auth is absent. Validate trusted exact Host/Origin including port, session/CSRF, strict schemas, revision and permissions on every operation. Bind loopback; refuse unapproved LAN/public access. Network deployment requires HTTPS; localhost HTTP is not encryption.
3. Add masked write-only credential setup through EKAS's backend, never browser-to-OpenAI requests. Keep raw input transient, clear after submit/cancel/navigation, never persist or echo it. Typing necessarily places it in browser memory; masking does not defeat malicious extensions. GETs expose metadata only. Use an OS credential store/established manager adapter; fail closed without it. Preserve environment-managed credentials as read-only “Managed by server configuration”. Atomic replacement failure retains the prior credential; blank input never deletes it. Removal is explicit and is not OpenAI revocation.
4. Separate Save settings, Set/Replace/Remove credential, Test connection, Enable AI and Disable AI. Save never calls a provider. Test is an explicitly confirmed tiny synthetic inference, states potential cost, uses the original cumulative USD20 ledger/reservations and prevents duplicates; a models-list/auth check is not inference proof. Key/model changes invalidate relevant current tested state. Disable prevents new requests; in-flight/unknown usage stays accounted. No key/restart/model reset creates allowance. Preserve existing pricing/independent-review gates, with trust/receipt designs clearly proposed choices, not source-mandated bureaucracy.
5. Add API/UI/security-boundary regressions, full unchanged predecessor validation, portable packaging and independent review. No real credential, journal migration, security provisioning or paid test is performed by this work.

OpenAI recommends backend API usage rather than deploying provider keys in clients. A protected administrator form submits a user-entered credential once to EKAS's backend; it does not embed a provider key into application API calls. [OpenAI key safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety).

Secret lifecycle/auditing and minimal transient plaintext exposure inform this design. The particular adapter/transaction choices below are implementation proposals. [OWASP secrets](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html). Identity verification and authorization are distinct; existing identity integration need not be replaced by a new enterprise IdP. [Microsoft identity](https://learn.microsoft.com/en-us/azure/architecture/guide/multitenant/considerations/identity), [OWASP authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).
