# V77 provisional server regression status

V77 addresses the independently reported V76 regressions. It is still a synthetic prototype with an explicit scripted fake provider. No live OpenAI activation, credential read, provider spend, real backend mutation or production/security acceptance is claimed. V76 remains immutable and preserved.

The old fake provider only queried FPY in the existing selection. It could not open a supported case from a fresh conversation, restore a refused scope, or format a table. A second defect paired a null withheld view with the original workflow snapshot, violating capture validation.

The corrected provider requests `canonical_turn` for the exact submitted user question. The canonical service prepares its genuine existing context/analytics/workflow transition in an ephemeral transaction snapshot. The final response atomically commits the same canonical captures after source, version, policy, cancellation and full-state checks. A separate provider supplement cannot replace the authoritative answer, chart, scope or semantic proof. No preview snapshot is persisted or made another case authority. Unsupported claims and concurrent repository changes prevent the entire prepared transition from committing. Supported original service behavior and its existing validators are retained.

Read-only model turns now keep the workflow snapshot null whenever their view is withheld. Explicit `Show FPY`/`Display first-pass yield` resolves the exact current eligible percentage; asset/revision/shift/site clarifications cannot revive a nearby result. OtherPlant/OtherSite wording is admitted by new scope schema4. Schema1-3 historical captures retain their original labels, timestamps and status rather than being reinterpreted.

The scripted preview delegates genuine service results, including charts/tables and controlled workflows. It is deterministic and remains disclosed as fake. The runtime uses an explicit test delay of1500ms before each provider round (typically two rounds,3000ms); this creates a controllable precommit Stop interval and is not a production-performance claim.

Stop aborts pending generation/prepared publication. A commit may already have occurred before Stop reaches the server. The UI therefore says that it stopped waiting and offers `Check saved operation`. That read-only control checks the same operation: held operations are not regenerated; already committed results are reopened with their original capture. Controlled normal HTTP UI checks cover both precommit cancellation and delayed-delivery postcommit reconciliation. Durable browser operation-cursor recovery after reload remains open; ordinary saved history and server operation/idempotency persistence are separate preserved mechanisms.

Synthetic role selection uses a server-owned session, fixed registered synthetic asset grant and public per-session policy identity. Role survives restart, unexpected authority/corrupt originals fail closed, and a request's role assertion must match the server session. Queued writes and delegated governed-record responses/commits recheck authority. This is role simulation, not production login or a grant to a live backend.

The server-only OpenAI Responses adapter and configurable budget authority are implemented and mock-tested. Import is inert. The adapter requires an injected server key, model, output cap, fetch capability and durable budget authority. No environment/key is read by the preview. Budget tests use fictional configured prices; no current model-pricing or new user-approval claim. Reservations are cumulative and nonrefundable; in-flight/unknown usage, expiry, model mismatch, corruption and persistence failure fail closed. Exclusive budget store ownership, live activation gates and complete unknown-usage/unknown-commit lifecycle remain unfinished.

Tom/GLiDE mapping remains a separate integration step against the actual production contract, trusted principal, masks, persistence/concurrency and audit semantics. No production endpoint compatibility is asserted. That contract's absence does not block this provider-neutral local server work.

Owner logs include earlier failed runs and scoped passing checks. Their counts overlap and do not establish full acceptance. Full-suite and compiled-server results must be read from the exact final evidence/handoff. Native chart/Grid/tooltip/table/export, all original UX/capability/census counterparts, role/adverse/recovery/performance/IME/native chooser and human/security acceptance remain open.
