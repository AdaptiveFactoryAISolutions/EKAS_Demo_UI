Minimal seam: native IndexedDB document store for the service and workspace; serialized transactional compare-and-swap against exact prior document, transaction-completion acknowledgments, no auto-delete. Preserve async mock service/query/resource schemas and ordinary memory-only clients. Sync localStorage remains an explicitly identified compatibility mode where IndexedDB does not exist; no silent fallback after a native database failure. Corrupt/incompatible originals remain exportable and block admission. Restore/reset are explicitly initiated only; backup export must include both stores and unsaved drafts, never omit indexed records.

Service: async repository initialization and commit; publish state/return success only after committed transaction. Serialize mutating requests to preserve sequence/idempotency under concurrency. Failed transactions preserve old durable state and exact snapshots, return typed STORAGE_UNAVAILABLE and permit safe retry.

Workspace: preserve synchronous UI method semantics as an explicitly pending local draft; serialize durable snapshots, acknowledge success through flush/receipts, expose persistent pending/failed state with export/retry. Failure blocks further durable writes and success notices until resolved; current unsaved draft stays recoverable, not silently rolled back or evicted. Cross-tab version conflicts require export/reload rather than automatic overwrite. All success-notification paths must bind to actual successful commits; sync errors must be returned rather than swallowed.
