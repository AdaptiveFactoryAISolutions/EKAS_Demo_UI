# Canonical local simulation integration

The authorized goal is a self-contained manufacturing chat/workspace with complete, meaningful synthetic backend/data coverage and actual Highcharts/Dashboards/Grid. This design follows the V88 census and starts after V89 freezes. It preserves the five-area shell, existing case journeys, protected inputs, old captures and the visual baseline. It does not activate OpenAI, real authentication, Tom's backend or production dispatch.

Use additive units in a new isolated candidate. Keep business state in the existing canonical repository and expose it through proposed typed manufacturing routes. UI state may select a pane or preserve an unsubmitted draft; it must not become a second owner/action/verification ledger. Existing earlier decision-support localStorage stays read-only, with explicit reviewed import where useful.

## 1. Decision support

Add a typed decision-support service and a canonical Explore subpane. Read the actual selected conversation, workflow and source dependency projection; derive owner, action, plan, verification, sustain and readiness from them. Persist only new observation/proposal/review/assumption records, with source references and expected versions. Do not copy workflow status into them.

`DecisionScopeRef` carries conversation ID/version, investigation ID/version, as-of, source row/version and active plan version. Writes compare this reference against authoritative state before committing. Unsupported/paused/comparison/training cursors cannot mutate the retained manufacturing case. Observations remain attributed unverified synthetic notes; PM proposals remain held proposals, not a released PM program. Handover acknowledgment does not accept ownership; existing assignment guards remain authoritative. Lessons retain supported/refuted/inconclusive distinctions and never become confirmed cause automatically.

Parameterized what-if calculations store assumptions, use the selected case's governed units/standards, distinguish physical recovery/usable capacity/saleable output/gross contribution/cost/validated benefit, and leave validated financial benefit unavailable. Portfolio assumptions are explicit, with source eligibility and constraints; no worker ranking or implicit real staffing claim. A consolidated JSON review packet captures exact linked versions and historical/current qualification, not just one chart.

Display all 56 source dispositions with concrete current implementation/held/missing states. A disposition alone never means implemented. Scope deeper genealogy, localization, retention and disruption work explicitly rather than concealing them behind activation gates.

## 2. Contract identity

Keep `ekas-proposed-v1` for compatibility; add an explicit current prototype revision and additive route/capability schema. Update current API documentation and generated artifact identity together. Older captured replies/contract references retain their original versions. Proposed synthetic paths do not claim compatibility with Tom's exact API/auth/version.

## 3. Complete governed metric scenarios

Retain ordinary training defaults and their missing/qualification outcomes. Do not invent ordinary measurements or silently replace them with scenario data. Expose a clearly named complete synthetic scenario catalogue using the existing raw positive-domain records and policies; independently check all 178 definitions, required inputs, units, scope, known-time, sufficient statistics and record consistency.

The complete scenario view chooses an explicit declared context/cutoff. Saved results retain that namespace and time. Multiple metrics with different horizons/units are separate results, never one pooled plant claim. Cp/Cpk/Pp/Ppk require the synthetic raw protocol and eligibility evidence; arithmetic-only examples cannot become observations. Root cause and financial realization remain unconfirmed/unvalidated. Original Northworks input records and current case calculations are never backfilled from another namespace.

Add typed manufacturing metric catalogue/query/result paths to the same local repository/transport and explicit dataset selection in chat/metrics. Preserve original investigations as inactive retained cursors when a scenario is selected; return requires explicit user selection. No default fake values or metric/plant substitution.

## 4. All 85 Guide workflow bindings

Create a registry for each retained workflow: actual surface, existing public control target, callable UI/service action, required inputs, authority/readiness, resulting receipt or read-only observation, and unavailable/held reason. Audit every entry against source. Generic purpose/first-field/details steps do not count as task-specific bindings.

Guide focuses/explains public enabled controls; it does not submit, save, authorize, delete, send, reset, export or change a clock on the user's behalf. Business completion requires an exact new receipt in the same context/version; skip/reading never completes work. Preserve drafts and exact invoker focus, including Show me outside the Guide. Held security/native print/chooser/genuine IME checks remain held; source mapping is not permission to reroute them.

## Validation and authority

Each unit has meaningful failing regressions, typed service tests, public source UI tests and compiled HTTP checks. Verify protected inputs/captures and current journeys after integration, then freeze source/static/server/package hashes for independent native/domain review. All 82 original requirement texts/mappings remain; no whole closure without full criteria.

Temporary OpenAI activation needs reviewed pricing/budget and secure server-side credentials. Tom's exact API/auth/version gates later conformance only. No key is configured and no live calls are authorized by this plan. Existing security, licence and human verdict gates remain separate.
