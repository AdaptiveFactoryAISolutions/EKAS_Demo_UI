# Dependencies and contracts (proposed, not provisioned)

| Dependency | Implementation/test scope | Operational condition |
|---|---|---|
| Existing React19.2.7/TypeScript6.0.3/Node20.20.2 runtime | Reuse installed stack and established styles; no new UI library needed | Exact final artifact/build reviewed |
| ServerAdminAuth adapter | Trusted server principal/session, installation/tenant scope and granular AI-admin grants; fixture sessions for tests | Reuse genuine backend identity, or operator-approved local ownership/bootstrap; absent means deny. No new enterprise SSO mandate |
| Safe ingress | Exact configured Host/Origin/port, loopback binding, CSRF/session, body bounds/no credential body logs | Approved local administrator context; HTTPS for network deployment. Plain localhost HTTP is not encrypted. No TLS/trust provisioning now |
| SecretStore adapter | Fake atomic store for tests; opaque versioned references, staged write then atomic metadata CAS retaining old reference on failure | OS credential store or established secret manager installed/unlocked for server account. Proposed Linux bridge: libsecret-tools/Secret Service plus unlocked keyring/D-Bus session, or Tom's existing manager. No plaintext fallback or application encryption key beside ciphertext |
| Durable settings/audit store | Non-secret settings, version/CAS and safe operation metadata; no secret value or request body | Exclusive/atomic persistence and recovery semantics; conflict never silently overwrites |
| Existing R5 budget/review authority | Same non-refundable cumulative accounting, original history, expiry and unknown-usage halt; fake fixtures only now | Reviewed pricing/current journal and existing independent security acceptance still required. No new receipt mandate beyond approved mechanism |
| Fixed provider adapter | Server-held OpenAI Responses endpoint/model allowlist; explicitly distinct mock/future-backend | No arbitrary endpoint field; Tom production auth/API contract remains supplied by engineer |

Suggested routes: GET /api/v1/admin/ai (metadata/settings/readiness only); PUT /settings (If-Match revision); PUT /credential (write-only secret, separate endpoint); DELETE /credential (explicit confirmation); POST /test (explicit cost consent + one-use operation ID); POST /enable; POST /disable. No GET performs mutation. Authentication/authorization, origin/CSRF and ingress checks precede sensitive-body parsing. Operational and mock state/secret stores are separate.

Permission matrix: anonymous401, authenticated non-admin403 for all protected routes; admin-read gets metadata only; admin-settings may save allowed non-secrets; admin-credential may replace/remove; admin-test requires both test grant and reviewed budget/security readiness; admin-enable requires enable grant/current tested revision/all activation gates; admin-disable may stop new requests. Permissions derive from trusted server identity, not posted role/tenant/verified fields.

Safe errors: unauthenticated/forbidden, origin/CSRF/transport refusal, schema/body limit, revision conflict, store unavailable/locked, replacement failed (old reference retained), unknown operation/cleanup pending, model unsupported, policy expired, independent review pending, budget exhausted/in-flight/unknown usage. No raw exception/provider/store output is echoed. Non-secret drafts survive validation errors; raw credential clears. Audit: authenticated subject/scope, operation ID, time, prior/new revision, outcome/reason code; no key, suffix, body, authorization header or key-derived fingerprint.

Primary supporting guidance: [OWASP REST](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html), [OWASP CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html), [OWASP logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html), [Secret Service specification](https://specifications.freedesktop.org/secret-service/latest/). A local bootstrap is a proposed deployment dependency, not a new SaaS identity provider or an already-installed authority.

Sensitive-client boundary: credential submission uses a dedicated fixed-path Admin client, not the existing generic EkasClient that records request bodies in traces. Raw credentials never enter useEkas/global persisted state or Guide inspection/observation/capture/export hooks. Only safe metadata enters audit/status. This is a required implementation boundary, not an already-tested feature.
