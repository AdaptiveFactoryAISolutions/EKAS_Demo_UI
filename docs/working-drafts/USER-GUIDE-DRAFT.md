# EKAS demo user guide — working draft

This is a synthetic manufacturing demonstration. The guide covers normal flows independently exercised on V65 and retained in V66 source. Fresh V66 release acceptance is pending. People, work orders, records, approvals and results are fictional; the demo does not operate equipment or update Tom's backend.

## Start with a question

Open the nominated review page and use Ask. New starts an empty durable conversation. Begin with “Investigate downtime.”, “Investigate speed.” or “Investigate quality.” Read the context and captured time before continuing: machine, part/revision, operation and job define the investigation. A saved answer keeps its original timestamp and source status.

Run sends the question. Wait for its result and visible feedback. If no result is visible, retain the draft and report the exact sequence; absence of a reply does not establish that no turn was saved. The first-Run interaction remains under independent review.

“Plant Review” opens the operating review. Its source-bound goals, actuals and gaps can lead into a specific investigation. Results describe the declared fixture and cutoff. Missing exposure, unavailable inputs or ambiguous scope must be resolved before treating a numeric result as eligible.

## Work through the normal investigation

The following wording was exercised in the independent normal synthetic downtime journey; the speed and quality journeys used the corresponding case evidence. Read the returned prerequisites and attributed evidence at every step.

| Step | Example question | What to check |
|---|---|---|
| Establish a hypothesis | Record the first hypothesis. | A hypothesis is not a confirmed cause. |
| Request an owner | Ask maintenance to own this. | Assignment request is separate from acceptance. |
| Record acceptance | Record their acceptance. | The correct fictional owner and current case must be attributed. |
| Recommend and request approval | Recommend the action. Then Request approval. | Recommendation, request and authorization are distinct. |
| Record fictional approval | Approve the action. | This decision does not prove performed work. |
| Move to known inspection evidence | Advance time to inspection at 15:15. | Later evidence becomes available only at an explicit snapshot. |
| Record performed proof | Record work. | Match the current plan and attributed synthetic work evidence. |
| Move to post-action evidence | Advance time to verification October20. | Verify comparable exposure and exact source membership. |
| Measure | Record verification. | Check primary endpoint, ten eligible shifts and quality/energy guardrails. |
| Record safety review | Record safety. | A separate qualifying safety record is required. |
| Accept the measured result | Accept measured result. | Measurement and acceptance remain separate. |
| Check sustainment | Advance time to sustain October27. Then Record sustain. | Latest eligible observations must meet the primary target. |
| Inspect recurrence | Advance time to recurrence November3. | Read the recurrence evidence; do not infer continuing success from an old accepted result. |

For downtime, the primary endpoint is feeder-jam60→30 minutes per eligible shift, target≤30. Speed targets≤35; quality targets FPY≥95. OEE supports the assessment. Recurrence alarms differ from sustain targets. Observed gains are not causal proof or verified financial savings. A repair is distinct from an unreleased engineering change.

## Inspect evidence and history

Use the evidence views to read work notes, event/source IDs, controlled-document versions and uncertainty. Native Highcharts charts and the connected Grid describe the same captured data. Read units and cutoff with the value. An unavailable result should remain unavailable.

A controlled quote can support a reviewed observation, hypothesis or recommendation without becoming a confirmed cause. Exact UTC claim reads use ISO syntax, for example “Show reviewed claims as of 2026-10-06T16:15:00Z.” Unsupported relative/offset/plain UTC formats require clarification. Claim-link fixes have V66 domain verification; fresh native closure remains pending.

History reopens saved conversation evidence. Old answers retain original clocks and qualifications. A new measurement does not inherit acceptance from an earlier result. Layout/export and broader mobile/keyboard behavior remain under release review.
