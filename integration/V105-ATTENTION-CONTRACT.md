# V105 proposed local attention API contract

Synthetic demo schema, not Tom backend conformance. GET /api/v1/manufacturing/attention/{investigationId} returns an exact case/cycle/context/version/asOf projection: current/historical/unassessed qualification, selected authored source, original envelopes grouped by canonical event/case, source/generation/known timestamps, explicit visibility/deferred/detail/overload budgets, original attention journal and available known snapshots. Actual dispatch/delivery/safety delivery/resolution/physical recurrence flags are false; physical alarm count null.

Existing investigation command endpoint supports select-notification-snapshot(snapshotId,sourceVersion,reason,confirmation=SELECT_SYNTHETIC_NOTIFICATION_SNAPSHOT) and record-notification-attention(groupId,generation,sourceVersion,operation,untilUtc only for snooze,reason,acknowledgeAttentionOnly=true,confirmation=RECORD_SYNTHETIC_NOTIFICATION_ATTENTION). Exact expectedVersion and original idempotency key remain mandatory. Read accepts viewer; ack accepts manager/supervisor/maintenance/safety; digest deferral/reopen accepts manager/supervisor/maintenance. Core cannot snooze/mute. Exact real UTC snooze future≤30min. One ack per canonical event generation; original-key replay is exact, fresh duplicate refuses. Journal40/member detail10/group32/envelope128 budgets; source exceeding policy holds new mutation. Visibility6/digest≤3, core never silently suppressed; overload disclosed.

Authoritative precommit refusal carries not_committed; conflicts/uncertain persistence never borrow safe refusal. Original actor/body/key and expected version must be retained for manual recovery. Later clock makes old source historical and demands an explicit eligible source; expired digest/new generation resurfaces notice policy, not physical recurrence. All local operations retain underlying manufacturing action/owner/verification/sustainment truth.

Natural reads: Show attention inbox; Why was I notified; Which notices failed delivery; What is deferred by attention policy; Show notification acknowledgment history. Optional capture policy1 binds the original source and qualification; no implicit ack or channel dispatch.

Real backend must provide durable event identity/generation, timestamps/version/cycle/context and notification routes, authorized channel semantics, delivery outcome/unknown recovery, role/asset authentication, durable idempotency/concurrency, acknowledgment/snooze policy and safety escalation conformance. Source-authored failed/unverified metadata does not establish a real route or delivery attempt. No external recipient is contacted by this demo.
